# CarpetFall Board

Доска задач команды с входом через Discord. Разделы растут снизу вверх, статусы
настраиваются, права берутся из ролей на вашем Discord-сервере, изменения
прилетают всем открытым вкладкам мгновенно.

Из зависимостей — только `express`. Данные лежат в одном файле `data/board.json`.

---

## 1. Приложение в Discord

1. Откройте <https://discord.com/developers/applications> → **New Application**,
   назовите как угодно (это имя увидят на экране входа).
2. Слева **OAuth2**:
   - скопируйте **Client ID** → в `.env` как `DISCORD_CLIENT_ID`;
   - **Reset Secret**, скопируйте → `DISCORD_CLIENT_SECRET`;
   - в разделе **Redirects** нажмите **Add Redirect** и впишите адрес
     `<ваш адрес>/auth/callback`, например:
     - `http://localhost:3000/auth/callback` — для запуска у себя;
     - `https://board.example.com/auth/callback` — для боевого домена.

     Строка должна совпадать с `BASE_URL` из `.env` символ в символ.
   - **Save Changes**.

Бота добавлять на сервер не нужно — используется только OAuth2 со скоупами
`identify`, `guilds`, `guilds.members.read`.

## 2. ID сервера и ролей

Включите в Discord: **Настройки → Расширенные → Режим разработчика**.

- **ID сервера**: ПКМ по иконке сервера → «Копировать ID сервера» → `DISCORD_GUILD_ID`.
- **ID роли**: Настройки сервера → Роли → ПКМ по роли → «Копировать ID роли».

Кто что может:

| роль | что доступно |
|---|---|
| `ADMIN_ROLE_IDS` | всё: создавать и удалять разделы, менять статусы, удалять таски |
| `EDITOR_ROLE_IDS` | создавать, править, двигать и удалять таски |
| остальные участники сервера | только просмотр |

Если `EDITOR_ROLE_IDS` оставить пустым — редакторами становятся **все** участники
сервера. Если пусто и `ADMIN_ROLE_IDS` — админов не будет вовсе, поэтому впишите
хотя бы свой Discord ID в `ADMIN_USER_IDS` (это запасной ключ на случай, если
роли перенастроят).

Кого нет на сервере — не пустит вовсе.

## 3. Запуск

```bash
npm install
cp .env.example .env      # и заполнить
npm start
```

Откройте `http://localhost:3000`, нажмите «Войти через Discord».

### На сервере с доменом

Поставьте перед приложением nginx с HTTPS и пробросьте всё на порт приложения.
`BASE_URL` должен быть боевым `https://...`, и такой же redirect добавьте в
настройках приложения Discord — иначе Discord вернёт `invalid_redirect_uri`.

```nginx
server {
    server_name board.example.com;
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        # живое обновление доски идёт через SSE — буферизацию надо выключить
        proxy_buffering off;
        proxy_read_timeout 1h;
    }
}
```

Автозапуск через systemd — `/etc/systemd/system/carpetfall-board.service`:

```ini
[Unit]
Description=CarpetFall Board
After=network.target

[Service]
WorkingDirectory=/opt/carpetfall-board
ExecStart=/usr/bin/node server.js
Restart=always
User=www-data

[Install]
WantedBy=multi-user.target
```

### На игровом хостинге (панель Pterodactyl и подобные)

Подходит, если у хостинга есть **Node.js-сервер** (или «Custom / Bot») в списке
типов сервера и можно получить **отдельный порт**. Спросите поддержку двумя
вопросами: «можно ли запустить Node.js-приложение» и «дадите ли дополнительный
порт (allocation) с доступом по HTTP». Если оба ответа «да» — дальше так:

1. Создайте в панели новый сервер типа **Node.js** (или добавьте его к
   существующему, если хостинг разрешает несколько).
2. Через файловый менеджер загрузите содержимое этой папки (без `node_modules`)
   в корень сервера — обычно это `/home/container`.
3. **Startup command** в панели:

   ```
   npm install --omit=dev && node server.js
   ```

4. Переменные окружения задайте в разделе **Startup / Variables** панели — или
   просто загрузите свой `.env` рядом с `server.js`, приложение прочитает его
   само. `PORT` трогать не нужно: панель передаёт `SERVER_PORT` и `SERVER_IP`,
   приложение их подхватывает.
5. `BASE_URL` — это адрес, по которому доска открывается снаружи:
   `http://<IP>:<порт>` или `https://board.вашдомен.ru`, если направите на неё
   поддомен. Ровно эту строку с `/auth/callback` на конце добавьте в Redirects
   приложения Discord.
6. Запустите сервер и откройте адрес в браузере.

Чего ожидать от игровых хостингов:

- многие дают только порт Minecraft и режут остальное — тогда доска не поднимется;
- на shared-тарифах Node.js часто вообще недоступен, только Java;
- диск в контейнере обычно постоянный — `data/board.json` переживёт перезапуск,
  но бэкапы всё равно делайте.

### Бесплатные и дешёвые варианты

- **VPS за 3–5 € в месяц** — самый предсказуемый путь: полный контроль, домен,
  HTTPS, рядом можно держать и сам Minecraft-сервер.
- **Render / Railway / Fly.io** — поднимается за пару минут, но на бесплатных
  тарифах файловая система обнуляется при передеплое, а `data/board.json` —
  это и есть вся доска. Нужен постоянный диск (обычно платный), иначе доска
  будет сбрасываться.
- **Хостинг, где уже стоит сайт CarpetFall** — если он умеет Node.js, доска
  логично живёт там же, на поддомене вроде `board.вашдомен.ru`.

### Через Docker

```bash
docker compose up -d
```

`.env` и папка `data` подключаются с хоста, так что доска переживает
пересборку образа.

## 4. Данные и бэкапы

Вся доска — это `data/board.json`. Бэкап = копия файла:

```bash
cp data/board.json backups/board-$(date +%F).json
```

Сессии нигде не хранятся: это подписанная cookie. Смените `SESSION_SECRET` —
и все разлогинятся.

## Как пользоваться доской

- **Разделы** — плашки внизу, таски растут вверх. Клик по плашке сворачивает
  раздел, двойной клик (у админа) открывает настройки.
- **Таски** — клик открывает редактор. Наведение мышью раскрывает описание
  прямо на карточке. Перетаскивание переносит таск между разделами и меняет
  порядок.
- **Статусы** — свои: название и цвет задаёт админ в «Статусы».
- Сверху: поиск, фильтры по статусам, «только мои», прогресс и зум (– / +).
- Правки видны всем сразу — перезагружать страницу не нужно.

## Если что-то не так

| симптом | причина |
|---|---|
| `invalid_redirect_uri` от Discord | `BASE_URL` и Redirect в настройках приложения не совпадают |
| «Вас нет на Discord-сервере команды» | неверный `DISCORD_GUILD_ID` либо человек правда не на сервере |
| «Недостаточно прав» при правке | роль не попала в `ADMIN_ROLE_IDS` / `EDITOR_ROLE_IDS`; после смены роли нужно перезайти |
| доска не обновляется у других | прокси буферизует SSE — `proxy_buffering off` |
| права не изменились после правки `.env` | перезапустите процесс и перезайдите на доску |
| Discord ругается на `http://` в Redirect | поднимите HTTPS (домен + сертификат) и поменяйте `BASE_URL` |
| страница не открывается по IP:порт | хостинг не пускает HTTP на этот порт — нужен другой порт или другой хостинг |
